# 深海余烬与流光水母 · Zone 1

2D 像素水下探索游戏的第一个可玩切片。Phaser 3 + TypeScript + Vite，推到 GitHub 就能在 Pages 上跑。

## 本地运行

```bash
npm install
npm run dev
```

## 部署到 GitHub Pages

1. 把仓库推到 GitHub
2. 仓库 **Settings → Pages → Source** 选 **GitHub Actions**
3. 推一次 `main`，`.github/workflows/deploy.yml` 会自动构建并发布

`vite.config.ts` 里 `base: './'` 用的是相对路径，所以放在 `用户名.github.io/仓库名/` 这种子目录下也不会白屏，不需要按仓库名改配置。

## 玩法

| 输入 | 行为 |
|---|---|
| 按住 `空格` / 鼠标左键 | 蓄力（伞盖收拢，阻力上升），松开喷射 |
| `Shift` / 鼠标右键 | 生物脉冲：照亮周围，并激活范围内的光敏继电器 |
| `A` `D` / `←` `→` | 转向 |
| 移动鼠标 | 切到瞄准模式 |
| `R` | 回到上一个检查点 |
| `M` | 静音 |

**目标**：Zone 1 全程漆黑，唯一光源是你自己。找到两台光敏继电器，用生物脉冲点亮它们，水压闸门就会开启，从东侧出口离开。

路上要躲巡逻机械眼的扫描视锥（红＝巡逻，紫＝已发现你）和会周期性放电的断裂线缆。地热排气口能把你向上顶，垂直竖井要靠它才上得去。

## 几个刻意的技术决定

**物理没走 Arcade Physics。** 水下手感的核心是阻力曲线：高速要衰减得快（阻力 ∝ v²），低速要几乎不衰减（保留漂移余韵）。Arcade 的 `drag` 是线性模型，做不出这个差异——要么高速拖不住，要么低速立刻停死。所以 `Jellyfish.integrate()` 是手写的，`dragLinear` 和 `dragQuadratic` 两根独立滑杆分别控制"低速黏滞"和"高速刹车"。

**转向能力随速度衰减。** 满速时几乎转不动，逼玩家提前规划路线，而不是随时变向。这是"惯性游动"的来源。

**蓄力收益走 easeOut 曲线，指数可调。** 用纯物理仿真跑过：指数取 2 时，50% 蓄力就能拿到 88% 的行进距离，蓄满完全没意义。调到 1.3 之后是 1.7 / 3.9 / 5.4 / 6.3 / 6.9 格，每一档都有可感增益。

**关卡是先当建筑建、再放道具的。** 第一版是反过来做的 —— 先画迷宫再按节奏撒道具，结果电线飘在水里、机器人没有理由、水道像随机洞穴。现在 Zone 1 是一座冷却水进水泵站：格栅 → 沉淀池 → 输水管廊 → 检修竖井 → 泵房 → 进水闸。道具从设施的破损方式里长出来：漏电线缆只挂在管廊顶部塌陷口两侧（供电干线沿顶敷设），维护单元只在成段的笔直管廊里巡逻，地热喷口只长在岩层裸露处。

**地形材质是从结构反推的，不是按高度切的。** 初版用一条 y=26 的水平线分金属和岩石，那条线在画面上毫无道理。现在的规则是：贴着房间两格以内的实心格是设施衬里，其余是海床岩层 —— 于是金属只出现在确实建过东西的地方，破口后面自然露出岩层。

**blob47 掩码表不是手写的。** `tools/fix_assets.py` 从图块自身的包边亮度反推出每张图对应哪个邻接掩码——金属的棕色包边和玄武岩的描边在露出边缘会压低该侧亮度，内拐角的缺口更暗。金属与玄武岩两套实测排列顺序一致，各 47 个唯一掩码，关卡里 1388 个实心格查表零失败。

**视锥是程序生成的，没用贴图。** R3 交付的视锥被 48px 帧边界硬切，有效长度只有 21px，末端是垂直切线，引擎没法按巡逻范围调长度。视锥本身只是单色 50% 抖动三角形，画出来反而更准。

**音效全是合成的，没有一个音频文件。** 这游戏的音效需求都是抽象的——喷射、脉冲、电弧、闸门、警报，没有一个需要真实录音的质感。合成的好处是风格天然统一、零素材体积、零版权问题，而且能参数化：蓄力音的音高跟着蓄力量走，给玩家一把"还能再蓄"的听觉尺子；喷射声的强度跟着蓄力量走；电弧和喷口按距离衰减，全场同响玩家会分不清危险在哪边。

整条总线末端挂了一个 1400Hz 低通——玩家在水下，高频本来就传不过来。Pulse 触发时把截止频率短暂推到 7kHz 再落回，听感像"水被推开了一瞬"，这个通透感比单纯把脉冲音做响有效得多。混响用反馈延迟代替 Convolver，便宜且够用。

**海雪那层粒子不是为了好看。** 没有它，玩家在空旷水域移动时没有任何参照物，会觉得自己没在动 —— 水必须是可见的介质。粒子系统是手写的而不是用 Phaser 的 ParticleEmitter，因为这里几种行为（被吸向移动中的目标、气泡上浮的正弦摆动、按相机视野补充）都要改每帧运动，发射器配置绕不过去。全部粒子用一个 Graphics 加法混合一次画完。

**顿帧比震屏更能传达"被打到了"。** 受击时冻结 110ms，画面上什么都不用加，感知强度就成倍上升。它不能用 Phaser 的 `timeScale` 实现 —— 那会连相机缓动和补间一起停掉，反而看不出停顿。所以顿帧期间只推进表现层（粒子继续飘、推镜继续收），物理和敌人全部冻住。

**黑暗用 RenderTexture + erase，不用 mask。** 光源每帧都在动且数量不定，重建 mask 比重画一次贵。

## 程序化环境资产

`tools/gen_env_assets.py` 用 PIL 直接画像素图，输出散落零件、倒地的机器人、
破损接头、机械门、沿顶线缆。全部锁在 36 色统一色板内、二值 Alpha，
脚本自带色板与 Alpha 自检，不合规直接 assert 失败。

```bash
python tools/gen_env_assets.py --out public/assets
```

这么做不是为了省画师的工，是因为**这类资产必须和场景绑死**：零件要落在地面上、
接头要贴在残构表面、线缆要按管廊走向接段。所以贴图里刻意不画"埋进沉积物"
那一层 —— 埋多深是摆放时按地形算的，画死了就只能配一种地形。

## 美术资产批次

`public/assets/` 里同时装着两批：

- **R3 主资产**（主角、图块、敌人、闸门、喷口、光效、过场）—— 经 `tools/fix_assets.py` 修复过
- **第一批开场资产**（标题 Logo、背景、族群、幼体、残骸、暗流、守炉者终端、碑文墙、8 个词根、对白框、菜单标记）

开场批次的 Tag 区间写在 `src/scenes/BootScene.ts` 的 `OPENING_TAGS` 里，按 spritesheet 网格切，不依赖 JSON 解析。任何一张缺失都会退回程序图形，游戏照样能通关。

## 字体

用的是 [Ark Pixel Font](https://github.com/TakWolf/ark-pixel-font)（OFL 1.1），12px 比例版。

全量中日韩是 534KB，对网页游戏首屏太重，所以做了子集化 —— 游戏里的文字是固定的，只嵌实际用到的字，**534KB → 28KB**。加了新文案要重跑：

```bash
python tools/subset_font.py <解压后的字体目录> --out public/fonts
```

漏掉的字会静默退化成系统字体，不会崩但一眼看得出来，所以改完文案记得重跑。

两条像素字体的硬规矩写在 `src/ui/theme.ts` 里：

- **字号只能用设计尺寸的整数倍**（12 / 24 / 36）。11px 或 13px 会让字形落在非整数像素上，糊得比系统字体还难看
- **resolution 要跟着设备像素比取整**。高分屏上画布按 CSS 像素算，不设 resolution 的话浏览器会把 12px 的字拉成 24 设备像素再插值；取整之后是 2 倍整数缩放，像素字体在整数倍下依然锐利

另外 Ark Pixel 是手绘字体，覆盖率随版本增长，**确实存在常用字尚未收录的情况**（2026.07.20 的 12px 就没有「毁」「瞬」）。子集化工具会把这类字打印出来，文案里换掉即可。

## 资产

`public/assets/` 里的文件是 `tools/fix_assets.py` 处理过的，不是 R3 原件。重新生成：

```bash
python tools/fix_assets.py <R3资产目录> --out public/assets
```

修复内容见 `ASSET_FIX_REPORT.md`，仍需画师返工的部分见 `ARTIST_TODO.md`。

游戏对缺失资产是容错的：任何一张图集加载失败都会退化成程序生成的占位图形，关卡照样能通关，右侧调参台的「缺失资产」一栏会列出来。
